# 운영체제의 개요
> OS 를 알아야지 애플리케이션이 CPU·메모리·디스크·네트워크를 어떤 비용과 제약 아래 사용하는지 설명할 수 있다.

## 1. 운영체제란?

운영체제(Operating System, OS)는 **애플리케이션과 하드웨어 사이에서 자원을 관리하고, 프로그램이 안전하게 실행될 수 있는 환경을 제공하는 소프트웨어**다.

애플리케이션은 CPU, 메모리, 디스크, 네트워크 장치를 직접 제어하지 않는다. 운영체제가 제공하는 인터페이스를 통해 필요한 자원을 사용한다.

```text
백엔드 애플리케이션 (Java/Kotlin, JVM)
                ↓
라이브러리 · 런타임 (JDK, JVM, libc 등)
                ↓
시스템 콜 (read, write, socket, accept 등)
                ↓
커널 (프로세스, 메모리, 파일, 네트워크 관리)
                ↓
하드웨어 (CPU, RAM, Disk, NIC)
```

애플리케이션이 어떤 자원을 사용하고, 어디에서 대기하며, 왜 느려지거나 종료되는지를 이해 해야한다.

---

## 2. 운영체제의 주요 역할

| 영역 | 운영체제가 하는 일 | 백엔드 실무 사례 |
|---|---|---|
| CPU 관리 | 실행할 프로세스와 스레드를 선택하고 CPU 시간을 배분한다. | 스레드가 지나치게 많을 때 문맥 교환 비용이 증가한다. |
| 프로세스·스레드 관리 | 생성, 실행, 대기, 종료 상태를 관리한다. | 서버 스레드 풀, 비동기 작업, 동시성 문제와 연결된다. |
| 메모리 관리 | 가상 메모리를 제공하고 물리 메모리를 배분·회수한다. | JVM Heap 설정, 메모리 부족, Swap, OOM과 연결된다. |
| 파일 시스템 관리 | 파일과 디렉터리, 권한, 캐시를 관리한다. | 로그 기록, 파일 업로드, 디스크 사용량 및 I/O 병목과 연결된다. |
| 입출력 관리 | 디스크와 네트워크 등 장치의 입출력을 중재한다. | Blocking I/O, Non-blocking I/O, 이벤트 기반 서버와 연결된다. |
| 보호와 격리 | 사용자·프로세스별 권한을 분리하고 자원 접근을 제한한다. | 파일 권한, 포트 권한, 컨테이너 격리와 연결된다. |

## 3. 운영체제의 구조

### 3.1 사용자 영역과 커널 영역

운영체제는 시스템을 보호하기 위해 실행 영역을 크게 나눈다.

| 구분 | 사용자 영역(User Space) | 커널 영역(Kernel Space) |
|---|---|---|
| 실행 대상 | 일반 애플리케이션, JVM, 셸 등 | 운영체제 커널, 디바이스 드라이버 등 |
| 권한 | 제한된 권한 | 하드웨어와 전체 시스템 자원에 접근 가능 |
| 장애 영향 | 일반적으로 해당 프로세스가 종료됨 | 오류 발생 시 시스템 전체에 영향을 줄 수 있음 |
| 자원 접근 | 시스템 콜을 통해 요청 | 요청을 검증하고 실제 작업 수행 |

애플리케이션이 하드웨어에 직접 접근하게 두면 다른 프로세스의 메모리를 침범하거나 시스템 전체를 망가뜨릴 수 있다. 따라서 일반 프로그램은 사용자 모드에서 실행되고, 보호가 필요한 작업은 커널에 요청한다.

### 3.2 시스템 콜(System Call)

시스템 콜은 **사용자 프로그램이 커널의 기능을 요청하는 공식 인터페이스**다.

대표적인 예시는 다음과 같다.

| 작업 | 관련 시스템 콜 예시 |
|---|---|
| 파일 열기·읽기·쓰기 | `open`, `read`, `write`, `close` |
| 프로세스 생성·실행 | `fork`, `exec` |
| 네트워크 통신 | `socket`, `bind`, `listen`, `accept`, `connect` |
| 메모리 확보·매핑 | `mmap` |

Java/Kotlin 코드에서 `FileInputStream`, `Files.readString()`, `ServerSocket` 같은 고수준 API를 사용하더라도, 마지막에는 JVM과 네이티브 라이브러리를 거쳐 운영체제의 시스템 콜이 호출된다.

```text
애플리케이션 API 호출
    → JVM/JDK 내부 구현
    → 시스템 콜
    → 커널이 파일 또는 네트워크 작업 수행
    → 결과를 애플리케이션에 반환
```

시스템 콜에는 사용자 모드와 커널 모드 사이의 전환 및 요청 처리 비용이 든다. 따라서 아주 작은 I/O를 지나치게 자주 실행하는 것보다 버퍼링이나 배치 처리를 이용하는 편이 효율적일 수 있다.

> API는 개발자가 사용하는 함수나 규약이고, 시스템 콜은 운영체제 커널에 작업을 요청하는 인터페이스다. 모든 API가 시스템 콜인 것은 아니다.
